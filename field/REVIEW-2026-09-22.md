# Pre-OTA engineering review — 2026-09-22

A full-codebase reliability audit of the connection path (idle → detect → connect →
handshake → data → disconnect), ahead of the next radio-to-radio test. Priority order:
connection reliability > protocol correctness > DSP robustness > diagnostics > bug fixes >
maintainability. Companion to `OTA-FINDINGS` and `TX-ONSET-FINDINGS`; the OTA-1/OTA-2
recordings under `%APPDATA%\aether-hf\recordings\` were the evidence for the timing numbers.

## Fixed in this pass (with tests)

1. **A keying failure no longer kills the daemon and strands a keyed transmitter.** The run
   loop turned any `PttError` from `station.capture`/`station.playback` into a fatal `?`
   (`main.rs::serve`), so a serial-write error, a dropped `rigctld`, or a CI-V read timeout
   exited the process *without* running the shutdown that releases the key — a rig keyed by
   CAT/rigctld would stay in transmit. Now the loop logs the failure (rate-limited),
   abandons the burst in progress (`Station::abandon_tx`), and keeps receiving; the engine's
   own timers retry or end the session. The "receive-only until the interface is fixed"
   design (`BrokenPtt`) was a fiction before this — the daemon died the moment anyone called
   or pressed Beacon/Probe/Tune.

2. **A dead sound card no longer leaves the key stuck for ever.** The key is released against
   the card's playback clock (ADR-0010); if the card stops delivering audio mid-burst (a
   dropped USB device, a sample-rate change) that clock freezes and nothing brings the key
   up — and the audio clock the session timers ride freezes too, so nothing times out. The
   loop now forces the key up on the wall clock after `AUDIO_STALL_RELEASE` (2 s) with no
   audio while transmitting (`release_on_stall`). This is also the only path by which the
   daemon notices a dead card at all.

3. **A probe is answered on a busy channel.** A station that decodes a probe marks its own
   channel busy for two seconds (`frame_hold`); with `wait_for_clear` on (the default) that
   held the station's *own* `PROBE_ACK` for longer than the prober waits, so every probe to
   a default station reported "no answer" — exactly the OTA-2 test sessions' "probe: no
   answer; calling anyway". A probe answer is a response to a frame addressed to us
   (§97.221(c)) and now bypasses the busy hold, like a session's own frames already do
   (`Station::start_pending`, `is_probe_answer`). Test:
   `a_probe_is_answered_even_with_wait_for_clear_on`.

## The top remaining risk — the floor family is dead on the air (not fixed)

ADR-0009's narrow floor family (`NARROW_FLOOR_LONG`/`SHORT`) carries connect, poll and
acknowledgement when a 500 Hz link runs its two slowest modes, and a connect request
alternates onto it from the third try so a station reachable only at the floor is still
called. **It decodes offline and never live.** A floor frame spans 33 728 baseband samples
(4.2 s); the streaming receiver only ever searches a window of `block + 2·lookback`
≈ 4 500 samples, and `detect_floor`'s guard (`sync.rs`) requires the *whole* frame to be in
that window, which can never happen live. Confirmed by a Rust test
(`stream::tests::a_floor_frame_streams_the_same_as_one_offline_call`, marked `#[ignore]` as
a repro: offline finds the floor frame, streaming finds none) and reproduced in the model.

Accepting the candidate on its preamble (as the ordinary path does) mis-locks by one symbol
— an 8-symbol repeated floor preamble is only pinned to the exact symbol once the
preamble→data boundary is visible — so the fix is a floor-aware search-back (announce the
floor preamble, then re-search from it once the body is in) or a dedicated floor lookback,
with a receiver-cost measurement (the narrow bank is not cheap), done model-first with an
ADR-0009 amendment. **Impact for the next test:** low if it runs strong-signal (the link
uses ordinary modes 2–4, which stream fine — every frame that decoded in OTA-1/OTA-2 was
QPSK modes 2/3/4). It bites weak-signal and DX narrow work below about −5 dB, where the
floor family is the whole point.

## Other confirmed defects, not fixed here (ranked)

- **A remote callsign the air interface cannot carry hangs the engine in `Connecting` for
  ever, transmitting nothing.** `LinkEngine::connect_as` sets the state, then
  `send_connect_with` returns silently when `ConnectBody::encode` rejects the callsign (a
  space, a dot, >9 chars), and the connect timer is only armed after a transmit — so nothing
  ever ends it. Reachable from the panel Call box and any control client (the VARA adapter
  guards it with `plausible_callsign`). *Fix:* validate both callsigns with `pack_callsign`
  at the top of `connect_as` (and `probe`, `TestPlan`) before touching state. Engine, so
  model-first.
- **DISCONNECT during `Connecting` does not cancel the call, and the host is never told a
  call failed.** `disconnect()` only sets a flag while connecting; the station keeps calling
  up to `connect_retries` (8) with widening backoff. And the VARA adapter sends `DISCONNECTED`
  only for a session it announced, so `no answer`/`aborted` after `CONNECT … OK` produces no
  line and there is no `CANCELPENDING` — Winlink/Pat/VarAC sit on their own timeouts. *Fix:*
  cancel on DISCONNECT while connecting (or map the host's DISCONNECT to `abort` there), and
  emit `DISCONNECTED` on any `disconnected` event while a call was outstanding.
- **Data written to the host data port while not `Connected` is silently discarded**, and a
  host that detaches mid-session leaves the session up and can leak delivered bytes to the
  next data connection. *Fix:* drain `to_radio` before applying a command; `abort` on
  command-port close if not idle; clear both pipe buffers at attach and on `disconnected`.
- **`Station::abort` does not drop bursts already queued** (`pending` is cleared only by
  shutdown and the watchdog), so a CONNECT held for a busy channel can still key after the
  operator aborted. *Fix:* clear `pending` in `abort` and on the `disconnected` event.
- **HARQ buffers can be poisoned or discarded by a low-confidence inferred frame**
  (`engine.rs` combine path): keep the previous buffer, not the merged one, when the failing
  frame's `mode_confidence` is below `MODE_RETRY_CONFIDENCE`.
- **An earlier phantom acquisition can hide a real frame that starts inside its claimed
  span** (`stream.rs` duplicate-span suppression, no strength comparison across calls), and
  a preamble can be reported *after* its own frame has decoded (ordering hazard for the
  link's start-of-frame signal). Fading-channel effects; low incidence on AWGN.

## DSP notes relevant to OTA

- **Rig frequency-offset tolerance is about ±100 Hz for decoding, not the ±300 Hz
  acquisition searches.** The band-limit FIR is applied twice on the live path and its
  −6 dB point is ~120 Hz beyond the outer carriers; at ±150 Hz the outer carriers are ~6 dB
  down. Keep both dials within ~100 Hz. (Dropping the redundant second FIR would widen this;
  measure `bench_phy` at ±100/±150 Hz first.)
- **The reported SNR is an EVM ceiling** (`snr_3k_db`, pilot residual inside the frame), so
  ALC/PA clipping, front-end IMD and AGC steps all lower it — this is the OTA-2 "26 dB
  spectral, 7 dB reported" finding, and why the rate controller stepped *down* on a clean
  path. Set drive with **Set drive** (the real waveform), not the tune tone; keep the rig out
  of ALC limiting; consider the RX attenuator at short range.
- **The receiver was search-bound — fixed 2026-09-23.** Replaying the OTA-2 base test
  session at 20 ms blocks ran 5.0× real time with 622 passes over the old 250 ms backlog,
  and the 10-mile session of 2026-09-23 ran 10.4×: the per-call `feed` re-searched
  `block + 2·lookback` every call, repeating ~90 % of its correlation work. The streaming
  receiver now computes each bank row once and caches it by absolute position (ADR-0010
  §6); the same session replays at 0.79× real time with no pass over 250 ms, and an idle
  listen at 0.18× (was 0.55×), with identical frames found.

## Diagnostics — recommended for this test (mostly config, some engine follow-ups)

- **Turn on the machine-readable log now, no code change:** set `[log] file = "aetherd.log"`
  and `[log] format = "json"`. The desktop app already files the daemon's stdout to
  `%APPDATA%\aether-hf\aetherd.log`; JSON makes it parseable and it already carries every
  mutating control request, the `connected`/`disconnected` reason, `ptt` keyed/released,
  busy transitions with level/floor/delta/margin, and `loop:` stalls.
- **Leave `[record] tx_audio` off** unless the transmit envelope is the question — its WAV+JSON
  is written synchronously at unkey, exactly when the peer's reply is due.
- **What is missing and worth adding (engine, model-first):** a `disconnected` line already
  gives the reason, but the *why* underneath is silent — each timer expiry and retry
  (`wait: ack, retry 3/8`), each connect attempt (`connect try 3/6`), the ACK's
  base/bitmap/mode/flags on both send and receive, HARQ rescues, re-encodes, and each
  *ignored* frame with its reason (wrong session, wrong bandwidth, not addressed to us).
  These all pass through `Action::Event` → `Station::note` → the log and the sidecar, so no
  new plumbing is needed. Also: start the auto-recording on a call *initiated* (not only on
  `connected`) so a failed connect leaves a replayable sidecar, and write per-session
  counter deltas (OTA-FOLLOWUPS item 4).

## Preserve after a failed connection (from BOTH stations, before restarting the daemon)

`%APPDATA%\aether-hf\aetherd.log` (and `aetherd.prev.log` if already restarted),
`recordings\<stamp>_*.json` and `.wav`, `recordings\tx\*` if `tx_audio` was on, `heard.json`,
`station.toml`. Note both machines' clock offset at the time (nothing on the air carries
time; the two files are related only by the system clocks and by pairing A's `sent` frames
to B's received frames).

## Follow-ups landed 2026-09-23, after the first 10-mile test

- **The busy indicator sat on with nothing on the air** — a real defect in the shape path,
  not RFI to chase: it judged a narrowband peak against the passband's own median, which the
  band filter's near-zero skirt bins drag down, so a station's own faint spur (present with
  the antenna disconnected, 42 dB "peaked" at −52 dBFS) latched busy on any dial. The peak
  is now also weighed against the learned noise floor (`SHAPE_PEAK_FLOOR_MARGIN_DB`): a real
  signal's peak stands at or above the floor even under an AGC, a spur sits ~12 dB below it.
  On the recordings: antenna-off and the 7076 kHz listen fell from 100 % to 1–3 % shape-busy,
  FT8 stayed ~70 % busy, and the existing +4 dB weak-signal test still fires.
- **The operator could not tell when the stations connected.** A session banner now spans
  every tab in large type (green connected with the role, amber calling/closing, red ended
  with the reason, kept fifteen seconds) and a two-note chime plays on connect and
  disconnect (Web Audio; the first click unlocks it; the *Chime* box on the Session tab).
- **The receiver's per-call cost** — fixed; see the DSP note above and ADR-0010 §6.
